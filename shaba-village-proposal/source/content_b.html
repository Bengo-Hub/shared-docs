Architecture principles

  • Single data owner. Each record has one home. estates-api stores the treasury invoice, account and plan IDs, the ERP employee ID and the auth user ID, and reads balances from treasury rather than keeping its own.
  • Single payment path. Only treasury-api talks to M-Pesa and the banks. estates-api asks treasury to invoice and to pay.
  • Event driven. Treasury publishes payment, invoice and payout events through a transactional outbox to NATS. estates-api consumes them idempotently by event ID.
  • Replica safe. Billing runs, reminders, SLA timers and purges run once per period across all replicas using shared leases.
  • Built for growth. Indexed tenant and estate keys on every table, keyset pagination, time-partitioned event tables, aggregates for reports and a read replica for heavy queries.
  • Standard stack. Go with Ent and Atlas migrations, Next.js, Helm and ArgoCD.
